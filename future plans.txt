───────────────────────────────────────────────────────────────────
  SEMANTIC CLIPBOARD SEARCH (Requires ONNX model + tokenizer)
───────────────────────────────────────────────────────────────────

Model:   all-MiniLM-L6-v2 (INT8 quantized ONNX, ~22MB on disk)
NuGet:   Microsoft.ML.Tokenizers (for BertTokenizer vocab.txt)
         Microsoft.ML.OnnxRuntime (already in project)
RAM:     ~30-40MB when active, 0MB when idle (lazy-loaded)
Latency: ~2-5ms per query on CPU

[ ] SemanticSearchEngine.cs — Core singleton class
    - Lazy-load ONNX InferenceSession only when search ≥ 3 chars
    - Auto-dispose after 60 seconds of search inactivity → 0MB idle
    - Thread-safe with SemaphoreSlim(1) around load/unload
    - ONNX options: IntraOpNumThreads=2, GraphOptimizationLevel=ALL
    - Same pattern as existing OnnxTableDetector.cs

[ ] Text Embedding Pipeline
    - BertTokenizer (vocab.txt) → input_ids + attention_mask
    - ONNX inference → last_hidden_state tensor
    - Mean pooling (weighted by attention mask) → 384-dim vector
    - L2 normalize → final embedding

[ ] Image Search via OCR Text
    - For image items: embed the OCR-extracted text (from existing
      Windows OCR in ClipboardItem.Ocr.cs)
    - No separate image embedding model needed
    - Images without OCR text: match on FileName only
    - Keeps RAM well under budget

[ ] Embedding Cache (Persistent)
    - Binary file at %AppData%/FlyShelf/semantic_cache.bin
    - Format: [int32 keyLen][utf8 key][384 × float32] per entry
    - Keyed by ItemId (stable hash) — survives app restarts
    - New items embedded in background on thread pool as copied
    - In FlyShelfViewModel.Persistence.AddClipboardItem():
      _ = Task.Run(() => SemanticSearchEngine.Instance.EmbedItemAsync(newItem));

[ ] Search Integration (MainWindow.Search.cs)
    - ApplySearchFilter() flow:
      query < 3 chars → keyword match only (unchanged)
      query ≥ 3 chars → keyword match + async semantic search
                       → merge results: keyword hits first,
                         then semantic-only hits ranked by
                         cosine similarity score
    - CancellationTokenSource for debounced semantic queries
    - Subtle "🧠" indicator when semantic mode is active

[ ] SearchResultComparer Enhancement
    - Add Dictionary<string, float> for semantic similarity scores
    - Priority 0 (highest): keyword match with semantic boost
    - Priority 1: keyword match only
    - Priority 2: semantic-only match (ranked by cosine score)
    - Priority 3: extension/type match

[ ] Model Files (ship with app)
    - Models/semantic/model_quantized.onnx (~22MB)
    - Models/semantic/vocab.txt (~226KB)
    - Downloaded from HuggingFace sentence-transformers/all-MiniLM-L6-v2

Example searches that would work:
    "deploy commands"    → finds "git push heroku main"
    "login credentials"  → finds "admin:p4ssw0rd@server.com"
    "meeting notes"      → finds "standup summary Q3 planning"
    "error messages"     → finds "NullReferenceException at line 42"
    "design colors"      → finds "#8B5CF6 indigo palette"
