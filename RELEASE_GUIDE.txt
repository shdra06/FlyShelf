================================================================================
  3. STEP 2 — BUILD THE RELEASE EXE
================================================================================

  The build pipeline is fully automated by Build_PC.bat. It does:

    [0/4] Kills any running FlyShelf.exe processes
    [1/4] Purges __pycache__ directories
    [2/4] Compiles: dotnet publish (Release, win-x64, self-contained, single-file)
          ↳ Obfuscar runs AUTOMATICALLY during compilation (MSBuild target)
            - Renames all classes, methods, fields (anti-decompiler)
            - Encrypts all string literals (hides secrets)
            - Obfuscated DLL is injected before single-file bundling
    [3/4] Computes SHA-256 hash of FINAL\FlyShelf.exe
          Saves hash to FINAL\FlyShelf.exe.sha256
    [4/4] AUTO-UPDATES version.json pc_sha256 field with the new hash

  IMPORTANT: The obfuscation is integrated into the .csproj MSBuild targets
  (FlyShelf.csproj lines 91-110). It runs obfuscar.console automatically during
  Release publish. You do NOT need to run ConfuserEx or Obfuscar separately.

  ── COMMANDS ─────────────────────────────────────────────────────────────────

  BEFORE BUILDING: If you suspect a stale NuGet cache (e.g., after version
  bump or dependency change), run restore first:

    > cd E:\exeapps\FlyShelf\FlyShelf_PC
    > dotnet restore FlyShelf.csproj -r win-x64

  THEN BUILD:

    > cd E:\exeapps\FlyShelf\FlyShelf_PC
    > .\Build_PC.bat

  AI AGENT NOTE: If the build fails with "Access to the path FINAL\FlyShelf.exe
  is denied", it means FlyShelf.exe is still running. Kill it first:

    > taskkill /f /im FlyShelf.exe
    > Start-Sleep -Seconds 2

  Then re-run dotnet restore and Build_PC.bat.

  ── OUTPUT ───────────────────────────────────────────────────────────────────

    E:\exeapps\FlyShelf\FlyShelf_PC\FINAL\FlyShelf.exe         (~80-90 MB)
    E:\exeapps\FlyShelf\FlyShelf_PC\FINAL\FlyShelf.exe.sha256  (hash file)

  EXPECTED BUILD TIME: ~30-60 seconds
  The build script auto-launches the compiled EXE at the end.

  4. STEP 3 — VERIFY THE BUILD
================================================================================

  After Build_PC.bat finishes with [SUCCESS]:

  A) CHECK BUILD OUTPUT said "[SUCCESS] PC Compilation Complete!"
     If it said "[ERROR]", see TROUBLESHOOTING section.

  B) CHECK OBFUSCATION OUTPUT said:
     "[OBFUSCATION] Obfuscar completed (exit: 0)"
     "[OBFUSCATION] ✅ Obfuscated DLL injected into publish pipeline"
     If it said "⚠️ Obfuscation failed", the EXE is unobfuscated but functional.

  C) CHECK THE HASH WAS UPDATED in version.json:
     The build script prints the hash. Verify version.json pc_sha256 matches.

  D) CHECK THE EXE SIZE:
     > dir E:\exeapps\FlyShelf\FlyShelf_PC\FINAL\FlyShelf.exe
     Should be around 80-90 MB. Much smaller = packaging failed.

  E) THE EXE AUTO-LAUNCHES after build. Verify:
     - App opens without crashes
     - Version in Settings/About shows {NEW_VERSION}

================================================================================
  6. STEP 5 — PUSH TO PUBLIC REPO (SAFE — NO SOURCE CODE!)
================================================================================

  ⚠️  CRITICAL: The public repo must NEVER contain source code.
  DO NOT run "git push public main" — that leaks EVERYTHING.

  REMOTE: public → https://github.com/shdra06/FlyShelf.git

  METHOD: Create a temporary orphan branch (no history), add ONLY the
  public-safe files, force-push, then delete the temp branch.

  COMMANDS (run ALL in sequence):

    > cd E:\exeapps\FlyShelf

    # 1. Create a clean orphan branch (no history)
    > git checkout --orphan temp-public

    # 2. Unstage everything
    > git reset HEAD -- .

    # 3. Stage ONLY the public-safe files
    > git add website/ version.json README.md LICENSE PRIVACY.md PRIVACY_POLICY.md

    # 4. Commit
    > git commit -m "v{NEW_VERSION} — Public Release"

    # 5. Force-push to public repo (replaces ALL history)
    > git push public temp-public:main --force

    # 6. Switch back to working branch
    > git checkout main --force

    # 7. Delete the temp branch
    > git branch -D temp-public

  AI AGENT NOTE: These 7 commands can be chained in a single shell invocation
  using semicolons (PowerShell) or && (cmd). Example for PowerShell:

    git checkout --orphan temp-public; git reset HEAD -- .; git add website/ version.json README.md LICENSE PRIVACY.md PRIVACY_POLICY.md; git commit -m "v{NEW_VERSION} — Public Release"; git push public temp-public:main --force; git checkout main --force; git branch -D temp-public

  ── WHAT GOES TO PUBLIC ────────────────────────────────────────────────────

    ✅ website/           → Landing page, pricing, payment APIs
    ✅ version.json       → Update checker for desktop app
    ✅ README.md          → Project description
    ✅ LICENSE            → License file
    ✅ PRIVACY.md         → Privacy policy
    ✅ PRIVACY_POLICY.md  → Extended privacy policy

  ── WHAT STAYS PRIVATE (NEVER pushed to public) ───────────────────────────

    ❌ FlyShelf_PC/       → All C# source code
    ❌ FlyShelf_Android/  → All mobile source code
    ❌ FlyShelf_Payment/  → Firebase Cloud Functions
    ❌ *.json (firebase rules, database exports)
    ❌ *.mp4, *.py, *.bat (debug files, scripts)
    ❌ RELEASE_GUIDE.txt  → This file (internal)
    ❌ obfuscar.xml       → Obfuscation config
    ❌ confuser.crproj    → Legacy obfuscation config


================================================================================
  7. STEP 6 — CREATE GITHUB RELEASE & UPLOAD ASSETS
================================================================================

  This step uploads the EXE and SHA-256 hash to GitHub Releases.
  The auto-update system in UpdateManager.cs reads from this.

  ── PREREQUISITE: CLEAR TOKEN ENV VAR ─────────────────────────────────────

    > $env:GITHUB_TOKEN = ""

  This prevents the GITHUB_TOKEN environment variable from overriding the
  keyring-stored credential. Run this EVERY TIME before using gh CLI.

  ── CHECK AUTH ────────────────────────────────────────────────────────────

    > gh auth status

  Must show: "✓ Logged in to github.com account shdra06 (keyring)"
  If not logged in:
    > gh auth login
    > gh auth switch --user shdra06

  ── CREATE RELEASE (2-step process for large EXE) ─────────────────────────

  AI AGENT NOTE: The EXE is ~80 MB and may time out if uploaded with the
  release creation command. Use a 2-step process:

  STEP A — Create the release with just the .sha256 file:

    > cd E:\exeapps\FlyShelf
    > $env:GITHUB_TOKEN = ""
    > gh release create v{NEW_VERSION} "FlyShelf_PC/FINAL/FlyShelf.exe.sha256" --repo shdra06/FlyShelf --title "v{NEW_VERSION} — {RELEASE_TITLE}" --notes "{RELEASE_NOTES_MARKDOWN}"

  STEP B — Upload the EXE separately (this may take 5-10 minutes):

    > gh release upload v{NEW_VERSION} "FlyShelf_PC/FINAL/FlyShelf.exe" --repo shdra06/FlyShelf

  AI AGENT NOTE: The EXE upload may take 5-15 minutes depending on connection.
  Do NOT kill the process prematurely. Wait for it to complete.

  ── IF A RELEASE ALREADY EXISTS (re-release scenario) ─────────────────────

  Delete the old release first:

    > $env:GITHUB_TOKEN = ""
    > gh release delete v{NEW_VERSION} --repo shdra06/FlyShelf --yes --cleanup-tag

  Then run Step A and Step B above.

  ── CRITICAL: ASSET NAMING ───────────────────────────────────────────────

  The EXE MUST be named exactly:  FlyShelf.exe
  The hash MUST be named exactly: FlyShelf.exe.sha256

  UpdateManager.cs searches for these EXACT filenames in the release assets.
  If you rename them, auto-update breaks for all users.

================================================================================
  9. TROUBLESHOOTING & ERROR RECOVERY
================================================================================

  ── BUILD FAILS: "Access to path FINAL\FlyShelf.exe is denied" ───────────

  CAUSE: FlyShelf.exe is still running (locked file).
  FIX:
    > taskkill /f /im FlyShelf.exe
    > Start-Sleep -Seconds 2
    > .\Build_PC.bat

  ── BUILD FAILS: "Assets file doesn't have a target" (NETSDK1047) ────────

  CAUSE: Stale NuGet restore cache after version bump.
  FIX:
    > dotnet restore FlyShelf.csproj -r win-x64
    > .\Build_PC.bat

  ── BUILD FAILS: Compilation errors ──────────────────────────────────────

  CAUSE: Code syntax errors or missing packages.
  FIX:
    > dotnet restore
    Read the error messages, fix the code, and re-run Build_PC.bat.

  ── OBFUSCATION FAILS (but build succeeds) ───────────────────────────────

  CAUSE: obfuscar.console not found or XML config error.
  IMPACT: EXE works fine but is NOT obfuscated (decompilable).
  FIX: Install Obfuscar globally:
    > dotnet tool install -g Obfuscar
  Then rebuild.

  ── GITHUB CLI AUTH FAILS: HTTP 401 ──────────────────────────────────────

  CAUSE: GITHUB_TOKEN env var overrides keyring.
  FIX:
    > $env:GITHUB_TOKEN = ""
    > gh auth switch --user shdra06
    > gh auth status

  ── EXE UPLOAD TIMES OUT ─────────────────────────────────────────────────

  CAUSE: The ~80 MB upload may stall on slow connections.
  FIX: Use the 2-step upload process:
    1. Create release with just .sha256: gh release create ...
    2. Upload EXE separately: gh release upload ...
  If it stalls again, check your internet connection and retry.

  ── HASH MISMATCH ON UPDATE ──────────────────────────────────────────────

  CAUSE: version.json SHA-256 doesn't match the uploaded EXE.
  FIX: Re-run Build_PC.bat (it auto-updates version.json), commit, push,
       and re-upload the EXE to the same release.

  ── USERS DON'T SEE THE UPDATE ───────────────────────────────────────────

  CHECK IN ORDER:
    1. Is the GitHub release published (not draft)?
    2. Is the tag correct (v{NEW_VERSION}, with the "v" prefix)?
    3. Does the release have FlyShelf.exe as an asset?
    4. Is version.json pushed to the PUBLIC repo main branch?
    5. Does pc_version in version.json match {NEW_VERSION}?

  The app checks for updates using TWO strategies:
    Strategy 1 (Primary):  GitHub Releases API → latest release tag
    Strategy 2 (Fallback): raw.githubusercontent.com/.../version.json

  ── WEBSITE NOT UPDATING ─────────────────────────────────────────────────

  CAUSE: GitHub Pages cache. Auto-deploys in 30-60 seconds.
  FIX: Hard-refresh (Ctrl+Shift+R). Check Actions tab:
    https://github.com/shdra06/FlyShelf/actions

  README.md                          → 2 references (badge + download link)

  ── BUILD PIPELINE ───────────────────────────────────────────────────────

  FlyShelf_PC\Build_PC.bat           → Release build script (use this!)
  FlyShelf_PC\obfuscar.xml           → Obfuscar configuration (auto-invoked)
  FlyShelf_PC\FlyShelf.csproj:91-110 → MSBuild target that runs Obfuscar
  FlyShelf_PC\FINAL\FlyShelf.exe     → Compiled, obfuscated release EXE
  FlyShelf_PC\FINAL\FlyShelf.exe.sha256 → SHA-256 hash file

  ── OBFUSCATION (AUTOMATIC) ──────────────────────────────────────────────

  Tool: Obfuscar (open-source, installed as dotnet global tool)
  Config: FlyShelf_PC\obfuscar.xml
  Trigger: MSBuild target "ObfuscateAssembly" in FlyShelf.csproj
  Runs: Automatically during "dotnet publish -c Release" with PublishSingleFile
  What it does:
    - Renames all internal classes, methods, fields to meaningless names
    - Encrypts all string literals (hides API keys, secrets, URLs)
    - Output goes to bin\Obfuscated\, then copied back before bundling
  Legacy: FlyShelf_PC\confuser.crproj (ConfuserEx config, NOT used anymore)

  ── UPDATE SYSTEM (code) ─────────────────────────────────────────────────

  FlyShelf_PC\Classes\UpdateManager.cs → Auto-update check, download, verify
    - Checks GitHub Releases API first, then version.json as fallback
    - Downloads FlyShelf.exe, verifies SHA-256, then prompts restart
    - Asset names must be exactly: FlyShelf.exe and FlyShelf.exe.sha256

  origin  → https://github.com/shdra06/FlyShelf-Private.git  (all source)
  public  → https://github.com/shdra06/FlyShelf.git          (releases/website)

  website\index.html    → Landing page
